# Claude Pet：Claude Code 桌宠

桌面常驻程序，用于实时指示 Claude Code 的运行状态：思考、执行命令、等待确认、任务完成、异常中断。

**零工具链安装**：使用 Windows 自带的 C# 编译器构建，不需要安装 Rust / Python / .NET SDK / Node。
**零 C 盘占用**：全部文件位于 `D:\ClaudePet\`，编译器为系统自带。

当前进度：**阶段 1（已可用）**。角色形象已由占位素材替换为**崩坏3 幽兰黛尔 Q 版**，8 个状态各有专属姿势。

## 阅读指引

本项目规模不大（约 4000 行），但若干模块的技术密度较高，相关内容均为实测记录。

**各部分的价值排序**（非阅读顺序）：

| 内容 | 位置 | 价值说明 |
|---|---|---|
| **抠图算法** | `src\Cutout.cs` | 当前算法可以一句话概括：删除所有属于背景色的像素。但其价值不在于这一简化形式本身，而在于注释中记录的失败路径：上一版素材的背景与人物皮肤仅差 5，只能依赖几何判据处理，代价是大量补丁以及一处「将角色整体删除」的缺陷。**正确的解法是更换素材（改用纯色背景），而非修补算法。** 此外，其诊断产物设计值得参考：每次运行输出 `.check` / `.mask` / `.alpha` 三张图与一份数值报告（含一项客观的残留自检指标），使算法的中间结果可经肉眼验证。对于过程不可见的算法，此类设计具有普遍适用性 |
| **窗口相关问题** | `src\Pet.cs` 的注释 | 分层窗口无法截图、点击不抢焦点需要三个机制同时生效、WPF 右键菜单无法关闭等，均属难以检索到的经验。每条注释均标注了「错误信息会将排查方向引向何处」 |
| **零安装构建** | `build.sh` | 仅使用系统自带的 `csc.exe`，不安装任何 SDK。附带涉及 csc 将 `/` 视为选项前缀、Git Bash 吞掉 `/nologo` 等非直观行为 |
| **图像流水线** | `src\SheetGen.cs` | 「单张图至 sprite sheet 加清单」的设计：清单与 sheet 由同一工具生成，因此始终一致。可作为「自洽性优先于灵活性」的具体样本 |
| **状态机与降级** | `src\Pet.cs` 的 `SetState` / `Tick` | 自动衰减、会话判死、非循环动画回落，展示了一个「不允许卡死」的状态机的实现方式 |

**建议的阅读顺序**：

1. 本文，尤其是**[已知问题](#已知问题)**一节，先明确哪些环节容易出错
2. `src\Pet.cs` 的文件头注释与 `BuildWindow()`，用于建立整体骨架
3. 按需深入具体模块（抠图 / 素材 / 网络对接）

**若干反直觉但具有普遍性的经验**（分散于各处注释，此处汇总）：

- **代理指标不可替代结果验证**：曾以 `SendMessage(WM_MOUSEACTIVATE)` 的返回值作为焦点保持的证据。该指标本身无误，但焦点仍被抢占。判定焦点是否丢失，须以实际键盘输入为准。
- **机制不通时应回溯根因，而非逐层修补后果**：右键菜单无法关闭这一现象曾经历六版修改，每版均在处理上一版的边界情况。实际的冲突只有一个，将其让开后，问题与既有补丁一并消失。
- **判据应精确而非宽容**：全屏检测若采用「窗口矩形包含显示器」，会将每一个最大化窗口误判为全屏（实测最大化窗口的矩形大于显示器）；改为「精确相等」方为正确。
- **全局指标不可替代逐项指标**：素材缩放曾让所有状态共用一个像素比，引入一张低分辨率图后，该图显示尺寸仅为其余的 1/3。**分辨率不一致时，全局共用必然错误**。
- **构建结果应依据退出码判断，不应检索输出文本**：中文输出为 GBK 编码，`grep` 会将其视为二进制文件并吞掉错误行，导致依据旧 exe 反复测试而误判「修改无效」。

**不宜直接沿用的部分**（本项目有意的局限，此处明确说明，以免产生误导）：

- **6 个 exe 各自独立编译，彼此之间不共享库**。这是「零安装加各工具可单独复制」的代价，其后果是 PNG 保存、建目录等逻辑一度重复 4 至 5 份。当前的折中方案是 `src\Common.cs`（**共用源码，非共用 DLL**）：csc 一次编译多个源文件，每个 exe 内各有一份副本，外部依赖仍为零。值得借鉴的是这一折中，而非「独立编译」本身。
- `Pet.cs` 单文件仍然偏大（右键菜单已拆分为一组 `Mk*` 函数，但整个文件已超过 2000 行）。可用，但并非良好的分层示范。
- 没有自动化测试。验证依赖 `tools\` 下的四个 PowerShell 脚本与人工查看界面。

## 使用方法

### 0. 获取项目

若已位于本机 `D:\ClaudePet\`，可跳过本步。在另一台机器上：

```bash
git clone <这个仓库的地址> D:/ClaudePet
```

**克隆后可直接编译并运行**：`assets\pet.png` 与 `pet.json` 已入库，无需预先制作素材。但**无法修改素材**：原始图与抠图中间产物均未入库（各约 30MB），如需重新执行素材流水线，须自行准备源图（见「替换角色素材」）。

### 1. 编译

在 Git Bash 中执行：

```bash
cd /d/ClaudePet && ./build.sh
```

无需安装任何组件，使用的是系统自带的 `csc.exe`。

### 2. 素材

仓库已附带一套素材（幽兰黛尔 Q 版），无需额外操作。如需恢复占位素材（蓝色果冻）：

```bash
./bin/MakeSprites.exe
```

该命令将重写 `assets\pet.png` 与 `assets\pet.json`（两者自洽，见问题 14）。
如需替换为自定义形象，请采用另一条流水线，见下文「替换角色素材」。

> **磁盘占用可随时释放大半**：`Cutout.exe` 每次运行均会在输出旁留下 4 个文件：
> `.check.png`（洋红底检查图）、`.mask.png`（抠漏标记）、`.alpha.png`（灰度 alpha）、
> `.txt`（连通块诊断）。**这些文件仅供人工查看，删除不影响任何功能**，下次运行 Cutout 会重新生成。
> 当前仓库中已完成清理（原为 36 个文件，共 60MB）。
> `youlandaierQban\` 中的原始图**不可删除**，它是 `Cutout.exe` 的输入，删除后无法重新抠图。

### 3. 启动桌宠

双击 `bin\Pet.exe`，或执行：

```bash
/d/ClaudePet/bin/Pet.exe &
```

桌宠默认出现在**屏幕右下角**。

**双击启动**：根目录的 `启动桌宠.cmd` 可直接双击运行（内部使用 `%~dp0` 定位 `bin\Pet.exe`，因此克隆到任意路径均可使用）；也可创建桌面快捷方式指向该文件。

> 桌面快捷方式（`.lnk`）**不入库**：它是二进制文件，且其中存储的是绝对路径，换机器后必然失效。仓库中仅提供可移植的 `.cmd`。

**桌面快捷方式**：`assets\pet.ico` **已入库**，可直接挂载：右键快捷方式，选择属性，更改图标，选中 `D:\ClaudePet\assets\pet.ico`。

该图标取自角色头部（`assets\cut\akimbo.png`），其位置**由测量得出，而非写死的比例**：
复用托盘图标的 `FindHeadBox()`，在上半幅图像内扫描虹膜对应的饱和蓝色以定位双眼，
再以眼部中心截取正方形（与托盘图标思路一致；此前按比例估算时，裁出的结果仅含少量刘海）。
因此**更换素材后重新生成一次即可，无需手工调整坐标**：

```bash
./bin/Pet.exe --icon "D:\ClaudePet\assets\pet.ico"
```

7 档尺寸一次生成：16/24/32/48 使用 DIB（兼容性最佳），64/128/256 使用 PNG。
每一档均**从原图重新采样**，而非放大低分辨率图。桌面、任务栏、大图标视图各使用不同尺寸，
若只提供一档（例如 `GetHicon()` 的 32x32），其余场景会被拉伸而模糊。

> 生成图标**无需先关闭正在运行的桌宠**：`--icon` 与 `--shot` 一样，均在单实例保护之前处理。

### 4. 接入 Claude Code

```powershell
powershell -ExecutionPolicy Bypass -File D:\ClaudePet\install-hooks.ps1
```

该命令会先备份 `~\.claude\settings.json`，随后写入 8 个 hook 事件。**重启 Claude Code 后生效**。

脚本会自行推导 `PetNotify.exe` 的路径（取**脚本所在目录**下的 `bin\`），
因此克隆到任意盘符、任意目录都能直接运行，不依赖上文示例中的 `D:\ClaudePet`。
需要指向别处时，用 `-PetExe <路径>` 覆盖。

卸载：

```powershell
powershell -ExecutionPolicy Bypass -File D:\ClaudePet\install-hooks.ps1 -Uninstall
```

如需预先查看将修改的内容，添加 `-DryRun`。

### 5. 开机自启（已配置）

**最便捷的方式：对桌宠点击右键，选择「开机自启」**。菜单项带勾选状态，点击即切换，
气泡会返回「已开启开机自启」或「已取消开机自启」。

如需使用命令行（例如编写脚本，或桌宠未运行时）：

```powershell
powershell -ExecutionPolicy Bypass -File D:\ClaudePet\install-autostart.ps1           # 开启
powershell -ExecutionPolicy Bypass -File D:\ClaudePet\install-autostart.ps1 -Status   # 查看
powershell -ExecutionPolicy Bypass -File D:\ClaudePet\install-autostart.ps1 -Disable  # 关闭
```

两条路径读写的是**同一个注册表值**，因此始终同步；菜单项的勾选状态也在每次打开菜单时实时读取，
不会显示过期状态。

写入位置为 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下名为 `ClaudePet` 的项，
**仅影响当前用户、不需要管理员权限**，也不修改任何系统级设置。

选择注册表 Run 键而非将快捷方式放入「启动」文件夹的原因：**启动文件夹位于 C 盘**，
而本项目的原则是 C 盘零占用，注册表项不新增任何文件。此外，任务管理器的「启动」标签页中
同样可见并可直接禁用（两处为同一个开关）。

## 状态映射

| Claude Code 事件 | 宠物状态 | 当前形象（幽兰黛尔） | 占位素材（8 个状态齐全） |
|---|---|---|---|
| `SessionStart` | awake | 双手握拳加两次小跳，气泡「**会话开始 · 项目名**」 | 蹦一下打招呼 |
| `UserPromptSubmit` | think | 盘腿托腮加省略号 | 歪头，冒省略号 |
| `PreToolUse` | work | 坐在书桌前写字加快节奏小抖 | 快速抖动，动感线 |
| `PostToolUse` | think | 盘腿托腮加省略号 | 回到思考 |
| `PostToolUseFailure` | error | 抱膝缩起发抖（眼中含泪） | 叉眼、波浪嘴、冒汗 |
| `Notification` / `permission_prompt` | alert | 挥手加感叹号，表示**正在等待确认** | 睁大眼、感叹号 |
| `Notification` / `idle_prompt` | sleep | 抱枕头睡在云上加慢呼吸 | 闭眼，冒 Z |
| `Stop` | done | 举拳欢呼蹦跳加闪星 | 欢呼跳跃，闪星 |
| `SessionEnd` | sleep | 同上（入睡），气泡「**会话结束 · 项目名**」 | 入睡 |

当前形象共 **8 张图，一个状态一张，无任何复用**（hooks 会发出的 8 个状态均有专属姿势）。
`assets\cut\` 中的抠图按**姿势**命名，而非按状态命名，这样后续重新分配状态时，
文件名不会产生矛盾：

| 状态 | 素材（姿势） | 动作 |
|---|---|---|
| idle | `akimbo.png` 双手叉腰等待 | 轻微呼吸浮动 |
| think | `sit.png` 盘腿托腮 | 轻轻歪头加「…」 |
| work | `desk.png` 坐在书桌前写字 | 快节奏左右小抖 |
| alert | `wave.png` 挥手 | 弹跳加「!」 |
| done | `cheer.png` 举拳抬腿欢呼 | 一次大跳加星星 |
| awake | `clasp.png` 双手握拳 | 两次小跳 |
| sleep | `pillow.png` 抱枕头睡在云上 | 慢呼吸（3fps） |
| error | `teary.png` 抱膝缩起发抖 | 小幅快速摇晃 |

> **各状态的视觉大小**由 `SheetGen.cs` 中的 `ScaleAdjust()` 手工微调。之所以需要它：
> 仅统一 bbox 高度并**不充分**。站姿中头部仅占 bbox 高度的约 23%，
> 而盘腿或蜷缩姿势可达约 32%，因此在相同 bbox 高度下，**坐姿状态的头部明显偏大**，
> 视觉上如同靠近了镜头。当前取值为：think 0.93、sleep 0.88、error 0.86（坐姿或蜷缩姿势缩小），
> work 1.05（有书桌撑满画框，人物反而显小）。修改这些数值后需重新生成 sheet 并**以肉眼验收**，
> 它们属于审美判断，并非计算得出。

若出现清单中不存在的状态名（例如修改了 hook，或新增状态但尚未制作素材），程序仍会**安全地回退至 idle**，
不会崩溃。这属于保底逻辑，并不表示当前存在素材缺失。

> `assets\cut\` 中的 `stand.png`（站立点赞）为**备用**素材：它原先占用 idle，
> 在改用上文「双手叉腰」的待机图后即不再使用。如需换回，将生成命令中的
> `idle=` 改回 `stand.png` 并重新生成即可。

> **云已保留。** 2026-09-12 素材重做后，`sit.png`（盘腿坐在云上）与 `pillow.png`
> （抱枕头睡在云上）中的云均予保留。此前版本素材的云线过浅，保留云会产生一圈淡米白色的
> 贴纸边，因而被抠除；新版素材的云与人物实体相连，抠除反而会使人像悬空。

`done` 与 `awake` 播放完毕后自动回到 `idle`；`alert` 会持续举手直至处理。
此外设有兜底机制：若在 think 或 work 状态停留超过 90 秒（会话异常结束），将自动回到 idle。

## 交互

**点击语义（2026-09-12 修改，请勿沿用旧习惯）：**

| 操作 | 效果 |
|---|---|
| **左键单击** | 角色说一句话（台词随当前状态变化，3 至 4 句轮换）。**状态不变**，气泡带「冒出」动画 |
| **左键按住拖动** | 移动位置（松开后记录） |
| **右键单击** | **切换至下一个状态**，气泡显示状态名 |
| **右键双击** | **弹出菜单** |
| 再次双击 `Pet.exe` | 召唤：已在运行的实例会冒泡显示「我在这儿！」，若位于屏幕外则自行移回 |

- **左键说话、右键切换状态**：左键为最高频操作，分配给**不改变状态**的行为（听角色说话）；
  切换状态这类有后果的操作则置于右键。
- **右键单击存在约 1/3 秒的迟滞**，这一点无法避免：系统必须等待确认「不再点击第二下」，
  才能判定是单击而非双击的前半部分。详见问题 25。
- 状态切换顺序：待机、思考、工作、等待确认、完成、回归、入睡、出错，然后回到待机。
  无需打开菜单即可查看全部八种姿势。
  其中「等待确认」与「入睡」为**持久**状态，切换进入后会停留（这是其固有语义），
  再次切换则继续向下；下一个 Claude 事件也会将其拉回正确状态。
- **右键菜单**：大小、透明度、回到右下角、重新载入素材、测试各状态、**开机自启**、
  **全屏游戏时自动隐藏**（均带勾选状态，可随时开关）、**隐藏到托盘**、退出
- **再次双击 `Pet.exe`**：不会启动第二个实例。已在运行的实例会冒泡显示「我在这儿！」，
  若因修改分辨率或更换显示器而位于屏幕外，会自行移回右下角。
  仅当该实例占用位置却无响应时，才会弹出一张 8 秒后自动消失的提示卡片。
- 窗口具有 `WS_EX_NOACTIVATE` 属性，**点击它不会夺走编辑器的焦点**（该特性此前并未真正生效，见问题 18）
- 位置、大小、透明度自动记录，保存在 `config.json`

### 全屏游戏时自动躲开

进入全屏游戏（如原神）时程序会**自行隐藏**，退出全屏后**自行恢复**，位置不变。
开关位于右键菜单（`全屏游戏时自动隐藏`，**默认开启**），保存在 `config.json`。
判定方式：每 500ms 轮询一次前台窗口，矩形与显示器**精确相等**才判定为全屏（连续 2 次同向才动作，约 1 秒）。

- 在真正的独占全屏模式下 DWM 本就不合成其他窗口，桌宠在该模式下**根本无法绘制**，
  因此该功能实际需要解决的只有**无边框窗口化全屏**，而这恰是可精确测量的模式。
  换言之，**检测失败也是安全的**。
- 全屏视频与浏览器 F11 同样会触发隐藏（按「不遮挡画面」的语义，这是预期行为）。
- **误判的处理**：若在不应躲开时躲开，右键将无法点击，此时**再次双击 `Pet.exe`** 即可召回，
  并会顺带**关闭该功能**且予以说明。
  （若不关闭，下一轮采样会再次将其隐藏，表现为「双击无效」。）如需重新开启，右键勾选即可。
- 多显示器：任一台显示器上存在全屏窗口即隐藏，不区分桌宠是否位于同一块屏幕。

### 隐藏到托盘（待命）

右键菜单选择「**隐藏到托盘**」：桌宠从桌面消失，**托盘（右下角通知区域）出现其头像图标**。

- **双击托盘图标**为恢复；**右键托盘图标**提供「显示桌宠」与「退出」。
  （隐藏后无法通过右键点击桌宠，托盘菜单是唯一出口，因此「退出」必须在其中保留一份。）
- **再次双击 `Pet.exe`** 同样可以召回（与上述全屏场景的救生机制相同）。
- **鼠标悬停在托盘图标上可查看当前状态**（「ClaudePet · 正在干活」），
  因此在「隐藏待命」期间也能了解 Claude 的运行情况。
- **隐藏期间为「真待命」**：Claude 事件仍照常更新其内部状态（托盘提示随之变化），
  但**窗口绝不会自行弹出**。若刚隐藏即被事件唤回，「隐藏」便失去意义。
- 与「全屏游戏时自动隐藏」是**两套独立状态**，互不干扰：
  手动隐藏后，进出全屏不会将其唤出。
- **隐藏状态不写入 `config.json`**：重启桌宠一律为可见状态。
  （若隐藏的宠物在重启后仍不出现，会让人误以为「双击无反应」，这是本项目最需避免的情况。）
- 托盘图标**不新增 `.ico` 文件**，而是从 `assets\cut\akimbo.png` 现场截取**头部**区域缩放生成，
  因此更换形象后托盘图标会随之变化。头部位置**并非写死的比例**，而是先定位双眼虹膜
  （图像上半部的饱和蓝色区域），再以其为中心截取正方形。按比例写死的那次，裁出的结果仅含少量刘海。
- **Windows 10 默认会将新出现的通知图标收入「隐藏的图标」折叠区**（任务栏的小箭头内），
  因此隐藏后**可能无法立即看到该图标**。这是系统设置，程序无法控制，将其拖至任务栏固定即可。
  图标不可见不影响功能：**双击 `Pet.exe` 同样可以召回**。

## 替换角色素材

两个工具构成一条流水线，**无需修改代码，无需重新编译**：

```bash
# 第 1 步：抠图。输入随便什么图（JPEG/PNG 都行，程序自己认格式，不信扩展名）
./bin/Cutout.exe "D:\ClaudePet\youlandaierQban\调整图片背景颜色 (1).png" "D:\ClaudePet\assets\cut\stand.png"

# 第 2 步：生成 sheet + 清单。每个状态各一张图；某个状态不写就沿用"默认"那张
./bin/SheetGen.exe "D:/ClaudePet/assets/cut/cheer.png" ^
    idle=D:/ClaudePet/assets/cut/akimbo.png    ^
    think=D:/ClaudePet/assets/cut/sit.png  ^
    work=D:/ClaudePet/assets/cut/desk.png    ^
    alert=D:/ClaudePet/assets/cut/wave.png   ^
    awake=D:/ClaudePet/assets/cut/clasp.png  ^
    sleep=D:/ClaudePet/assets/cut/pillow.png  ^
    error=D:/ClaudePet/assets/cut/teary.png
```

如需新增状态（例如增加一个「庆祝」）：在 `SheetGen.cs` 的 `States` 数组**末尾**添加一项，
并为其编写动作分支（按**名称**识别，见 `DrawFrame`），随后重新生成清单。
`Pet.cs` 依据清单中的名称识别状态，**无需修改代码**；点击循环也会自动包含新状态。
`awake` 曾经复用其他状态的帧（`--awake=<状态名>`），现在占用独立一行。
两种写法均受支持，但若状态表中已存在 `awake`，则不会再补充该复用条目（否则 JSON 中会出现两个同名键）。

两条约定（均为实测得出）：

- **缩放比例按状态各自计算**（按各自图像适配至最大，使屏幕高度一致）。
  曾将其「优化」为全局共用一个像素比，结果在换上一张低分辨率图
  （658x860，其余三张为 1760x2304）后，该图显示尺寸仅为其余的 1/3。
  **素材分辨率不一致时，全局共用像素比必然错误**。
  （2026-09-12 素材重做后，9 张图统一为 1792x2336，该问题暂时不会触发。
  但不应因此将「按状态各算」改回全局；下次引入尺寸不同的图时该问题会重新出现。）
- **动作参数与画稿无关**：更换姿势图无需修改 `SheetGen` 中的动作数值，
  它们描述的是「该状态应呈现何种感觉」。

每一步均会输出**可供肉眼检查的图像**。这不是可选项，因为抠图与边缘问题只能通过查看图像判断：

| 文件 | 检查内容 |
|---|---|
| `<名字>.png.check.png` | 合成到**洋红底**上：残留背景一目了然（奶油色在洋红上无法隐藏） |
| `<名字>.png.mask.png` | 在原始图上将判定为背景并抹除的像素涂红：抠漏人物一目了然 |
| `<名字>.png.txt` | 数值诊断：bbox、背景占比、**背景参考色与边框内吻合度**（判断该图是否适合键控）、被丢弃的连通块、**残留自检**（理想值为 0） |
| `<名字>.png.alpha.png` | 仅显示 alpha 的灰度图（头发内出现一片灰即表示填充侵入） |
| `bin\Zoom.exe <图> <x> <y> <w> <h> <倍数> <出.png>` | 裁取局部放大。给出两张图则并排对比，边缘细节依赖该工具检查 |

若抠图结果不够干净，**不要猜测参数**，应使用修正文件（每行一条，`#` 开头为注释）：

```
erase 512 440        # 从这个点开始，把颜色相近的连通区域抹成背景
keep  240 700        # 反过来：把误抹的恢复成人物
```

```bash
./bin/Cutout.exe <源图> <出.png> 150 "D:\ClaudePet\assets\cut\fixes.txt"
```

`Cutout.exe` 的完整参数（后两项均可省略）：

```
Cutout.exe <源图> <出.png> [背景容差] [修正文件]
           ...默认 30      ...默认空
```

- **背景容差**（第 3 个参数）：与背景参考色的最大通道差不超过该值即视为背景色。
  **不可随意放大**：实测人物中最接近背景色的是眼睛的青蓝高光，与青色相差 45，
  设置到 45 以上会将眼睛挖除（见**问题 24**）。取值为 `0` 时退化为空操作，一个像素也不会删除。

**素材要求：人物绘制在一块纯色背景上，且该颜色与角色差异明显。** 满足这一条件，抠图即归结为上述一句话。
更换素材后应先查看诊断中的「边框内吻合 %」，该值低于 80% 时会明确警告「该图的背景不是纯色」。

### 画布与清单的约定

- **屏幕上的显示尺寸 = `frameWidth / sheetScale`**。`frameWidth` / `frameHeight` 是 sheet 中每格的
  **像素**尺寸，`sheetScale` 为像素密度（生成器默认 2 倍：100% DPI 下属于超采样，
  将桌宠放大至 2 倍仍不失真，代价是文件体积略增）。
- **清单始终由生成器自行写入**（`SheetGen.exe` 或 `MakeSprites.exe`）：手工修改 sheet 尺寸却忘记
  同步修改清单是必然会出现的问题，因此不提供手工修改的入口。
- 如需恢复占位素材：运行 `./bin/MakeSprites.exe`（将重写 pet.png 与 pet.json）。
  `assets\cut\` 中的抠图不受影响，随时可用 SheetGen 重新生成。

**注意 WPF 不支持 GIF**，因此必须使用 sprite sheet，不能直接嵌入动图。
自行绘制素材可使用 Aseprite 或 Piskel（均免费）。

修改素材后无需重新编译，右键选择「重新载入素材」即可（窗口尺寸也会随之重算），或重启桌宠。

`verify-menu.ps1` 中还须显式展开子菜单（`ExpandCollapsePattern`）：WPF 子菜单折叠时，
其中的项尚未实例化，UIA 无法读取。若依赖「鼠标恰好悬停」，同一脚本会时而通过时而失败。
各脚本均以 `exit` 码报告结果：`0` 为通过，非 0 为失败或跳过。

## 已知问题

以下均为实际遇到的问题，而非理论推演：

1. **csc 将 `/` 视为选项前缀，即使它出现在路径中间。**
   `D:/a/b.cs` 会被拆分为 `D:` 与 `b.cs`，并报告「找不到源文件」。
   传递路径**必须使用反斜杠**，`build.sh` 中已遵循此规则。

2. **Git Bash 会将 `/nologo` 这类参数转换为路径。**
   编译前需执行 `export MSYS_NO_PATHCONV=1`。

3. **不要显式引用 `System.Web.Extensions`。**
   csc 自带的 `csc.rsp` 已引用它，重复引用会报 CS1703「重复的程序集」。

4. **含中文的 PowerShell 脚本必须保存为 UTF-8 with BOM。**
   否则 PowerShell 5.1 按 GBK 解析，直接产生语法错误。`install-hooks.ps1` 已添加 BOM。

5. **`Grid` 的 `RowDefinition` 未设置高度时默认为 star（各占一半）。**
   128px 的精灵图会被塞入一半高度的槽位而被裁切。
   必须显式设置 `Auto` 或 `Star`。

6. **WPF 透明窗口属于分层窗口，`CopyFromScreen` 无法截取。**
   如需验证渲染，应使用 `--shot` 离屏渲染，不应依赖截图。

7. **`Pet.exe` 运行期间无法重新编译**（文件被锁定），需先执行 `taskkill /F /IM Pet.exe`。

8. **编译器仅支持 C# 5**：不能使用 `$"..."`、`?.`、`nameof`、表达式体成员。
   `async/await` 可用。

9. **hook 命令必须使用 exec 形式，不要将状态拼接进 command 字符串。**
   `"command": "D:\\ClaudePet\\bin\\PetNotify.exe awake"` 这种整串写法，
   Claude Code 会将其交由 shell 解析。Git Bash 中未加引号的反斜杠是转义符，
   路径被解析为 `D:ClaudePetbinPetNotify.exe`，于是每个 hook 都报告
   `command not found`，桌宠全程收不到事件（表现为「桌宠无反应」，但 Pet.exe
   实际正在监听 47821 端口）。
   正确写法是将路径与参数分开：

   ```json
   { "type": "command", "command": "D:\\ClaudePet\\bin\\PetNotify.exe", "args": ["awake"], "timeout": 5 }
   ```

   `args` 存在时即为 exec 形式，Claude Code 直接 spawn 该 exe，不经过任何
   shell，因此反斜杠、空格、`$` 均不会被解析。`install-hooks.ps1` 已按此方式生成。

   排查提示：hook 一旦失败，Claude Code 会在会话中显示 hook 报错。若桌宠无反应
   却没有任何报错，则多半是 Pet.exe 未在运行，而非 hook 的问题。
   执行 `netstat -ano -p UDP | grep 47821` 若能看到 `Pet.exe` 即正常。

10. **提示不应使用 `MessageBox`。原因不是它会失效，而是它会抢占焦点。**
    对话框在系统中行为正常。（曾误认为该机器会自动关闭弹窗，并为此编写了测试；
    实际情况是人工点击所致，见下方注释。）需要避免它的原因是**桌宠的整体设计目标是不打断用户**：
    模态框会夺走焦点，并持续遮挡直至有人专门点击关闭。
    应改用 `ShowNotice`：无按钮，配合 `Topmost`、`ShowActivated=false`，并在 8 秒后自动 `Close()`。
    没有「确定」可点，用户便无需为一条提示移动鼠标。

    > 注：「机器会自动关闭弹窗」这一错误结论由本人提出，也已由本人删除。
    > 教训记录于此以免重蹈：观察到的 UI 现象若机器前坐着人，**应先确认是否由人所为**，
    > 再考虑系统原因。当时那个 2 至 3 秒的「规律」看似环境特性，实际上正是人类点击确定的速度。

11. **`ClampToScreen()` 在启动时是空操作。**
    它执行时 `win.Left` 仍为 `NaN`（配置中的坐标在 `ApplyScale` 之后才赋给窗口），
    函数首行 `if (double.IsNaN(win.Left)) return;` 会直接返回。
    于是 `config.json` 中一个屏幕外的坐标会让宠物**无声地停留在屏幕之外**：
    进程存在、UDP 在监听 hook 事件，但桌面上没有任何内容，表现为「程序根本没有启动」。
    现由 `EnsureVisible()` 兜底：启动时与收到「召唤」时各确认一次，显示不完整则移回右下角。

12. **`SetState()` 的早退条件缺少 `img.Source != null`，导致启动时窗口中不绘制任何内容。**
    `state` 字段初值即为 `"idle"`，因此启动时的 `SetState("idle")` 命中
    `if (s == state && anims[s].Loop) return;` 直接返回，`img.Source` 始终为 null。
    进程在运行、窗口大小与位置均正确、`IsWindowVisible` 也返回 true，但窗口内**完全透明**。
    表面看来是「桌宠根本没有启动」，而它实际上要等到第一个 hook 事件到来才绘制。
    该缺陷极难排查：截图无法捕获（问题 6），只有 `--shot idle` 渲染结果为 11KB（正常为 400KB）时才暴露。
    建议将 **`--shot` 逐个状态渲染一次**作为常规习惯（9 个状态仅需数秒）。

13. **颜色判据在「背景与人物同色」时必然失败；当时的解法是几何判据，而当前更优的解法是更换素材。**
    幽兰黛尔的面部 `(253,240,225)` 与上一版素材的背景 `(253,246,230)` 仅相差 **5**：
    阈值放宽会切掉人物，收窄则保留背景，无论如何调整都是错的。当时只能改用**几何判据**：
    将**深色描边**膨胀为「堤坝」（膨胀用于封闭描边的数像素断口），自四边漫水，
    堤坝之外即为背景。这样即便面部与背景同色也不受影响。
    但这**只是权宜之计**：它带有无法消除的副作用（边界切在描边外沿，会将角色**自带的白色
    贴纸边一并切掉**），还需再补充一道脆弱的颜色判据以清除被围死的背景块。
    2026-09-12 将素材重做为**纯青色背景**后，整套几何判据连同那些补丁**一并删除**，
    抠图简化为「删除所有背景色像素」一句话。参见**问题 24**。
    **教训：当判据难以编写时，应先考虑能否改变输入。在此问题上补充了三轮算法，
    而真正的解法是将背景换成纯色。**

14. **清单必须由生成器自行写入，不应手工修改。**
    手工修改 `pet.json` 的 `frameWidth` 却未同步修改 sheet（或反之），切分结果会是一堆错位的碎图，
    且不会报错。因此 `SheetGen.exe` 与 `MakeSprites.exe` 均自行写入清单，
    两者各自自洽：由谁生成 sheet，就由谁写入清单。

15. **`EnsureVisible()` 必须在 `win.Show()` 之后调用。**
    曾在 `BuildWindow()` 中调用一次，当时窗口尺寸尚未最终确定（`LoadSprites` 之后
    才会依据清单重算），于是它按错误的尺寸判断，将宠物移至右下角，并写回了 `config.json`。
    判据本身没有问题，**判断的时机**有问题。

16. **〔算法已删除，教训保留〕参数默认值不应是绝对值，应随输入的尺度变化。**
    本条原指几何判据中的「堤坝半径」：它封闭描边断口，而断口宽度随图像尺寸放大。
    658px 宽的图使用 5px 足够，而 1760x2304 的图使用 5px 则会漏，浅色头发被整片当作背景删除
    （背景占比从 58% 升至 68%），且**不会报告任何错误**。当时的修法是按图宽自动确定（`W/160`）。
    同一问题在 `SheetGen` 的缩放上再次出现（见「画布与清单的约定」第一条：全局共用一个
    像素比，引入一张低分辨率图即失效）。
    **排查此类问题的方法**：将参数由小到大扫描一遍，观察诊断中最能反映问题的量。
    漏时偏大，封闭后会出现明显拐点，继续增大则无副作用。
    当前的键控算法没有尺度参数（只有「颜色容差」，与图像大小无关），
    但**更换素材或分辨率后仍需重新确认一遍**。

17. **判断「单击还是拖拽」应比较窗口坐标，不能比较鼠标相对窗口的位置。**
    原实现使用 `e.GetPosition(win)` 在 `win.DragMove()` 前后取差值，但 `DragMove()` 内部
    会移动窗口，该差值会被污染：**明明是原地单击，也会被误判为拖拽**。
    实测症状为：点击宠物后它被移走（而非切换状态），且新位置被写入 `config.json`。
    现改为比较 `win.Left` / `win.Top` 的前后差值（阈值 4px），这是客观的「窗口是否移动」。

    曾尝试**自行实现拖拽**（用 MouseMove 自行移动窗口）以彻底避开 DragMove 的行为：
    点击判断确实变得干净，但该版拖拽自身存在缺陷（写入 `config.json` 的位置有误）。
    更重要的是，**使用注入鼠标的脚本根本无法可靠验证拖拽**：注入的「松开」收尾不干净，
    窗口会继续跟随真实光标移动（这正是那次 config 中出现 1102,156 这类异常坐标的原因）。
    结论：保留 DragMove（久经考验），**拖拽只能人工验证**；合成鼠标能够可靠验证的只有「单击」。

18. **「点击不抢焦点」需要三个机制同时生效；而它会导致右键菜单无法关闭，正确解法是「菜单开启期间临时放开」。**
    本项目一直声称窗口具有 `WS_EX_NOACTIVATE` 属性（README 与代码注释中均有此表述），
    但**该说法不成立**：`ShowActivated=false` 只保证第一次 `Show()` 不激活，WPF 不会因此添加该样式。
    实测 `GetWindowLong(GWL_EXSTYLE)` 为 `0x00080008`（TOPMOST|LAYERED）。后果是点击宠物后，
    正在输入的输入框会失焦。这是最核心的一项体验承诺，却从未真正生效。

    修复过程中发现**缺少任何一个都不行**：
    | 手段 | 单独使用为何不足 |
    |---|---|
    | `ShowActivated=false` | 只管第一次 Show |
    | `WM_MOUSEACTIVATE → MA_NOACTIVATE` 钩子 | 只拦截「鼠标点击引发的激活」；**WPF 处理鼠标输入时会自行主动激活窗口**，走的是另一条路径 |
    | `WS_EX_NOACTIVATE` 样式 | 有效，但它使窗口**永远无法失活**，而 WPF 右键菜单关闭的默认逻辑恰恰依赖「宿主失活」 |

    由此产生副作用：**菜单可以弹出，但点击空白处无法关闭**。为此修改了**六版**（采样鼠标状态、
    计算菜单屏幕矩形、让菜单项「认领」点击、各种宽限与保险），每版都会出现新的边界情况：
    矩形被算成 1x1、「打开菜单那一次按键被当作点击」、按住菜单项超过宽限时间菜单即自行关闭等。
    **这些都是在与同一个根因的后果较劲。**

    第一步：**菜单打开期间临时撤销 `WS_EX_NOACTIVATE`**
    （`MenuOpenedAllowActivate`），菜单项即可正常点击；关闭后（`MenuClosedRestoreNoActivate`）
    恢复该样式，并用 `SetForegroundWindow` **将焦点归还给原窗口**。
    代价是菜单开启期间焦点会短暂离开编辑器（使用菜单时本应如此）。
    同时删除了前六版积累的约 140 行 hack。

    第二步（**点击空白处仍无法关闭**，查阅社区后才得知原因）：WPF 的 `ContextMenu`
    将「关闭」挂在**鼠标捕获**上。原文表述为「它捕获鼠标，控件又被写死成『鼠标一失去捕获就关』，
    属于设计缺陷，可用原生 `Popup` 绕开」。因此在这类窗口上它确实不会关闭，与激活无关。
    最终解法：菜单打开期间铺设一层**近乎全屏的「点击接收层」**（`ShowMenuCatcher`），
    由**操作系统的命中测试**决定内外，不再进行猜测。三个要点：
    (1) 它必须是**近乎**透明（`alpha=1`）而非全透明，全透明的分层窗口点击会穿透，无法接收；
    (2) 必须用 `SetWindowPos` **明确排在菜单 popup 之后**，否则它会吃掉菜单自身的点击
    （这正是「菜单项点不动」的成因）；(3) 若获取不到菜单窗口句柄则**不铺设**（宁可无法关闭，也不能破坏菜单）。

    **三条教训**：
    (1) 文档中的断言（尤其是「最重要的那一条」）也须实测，不应直接继承。
    (2) **代理指标不可替代结果验证**：曾以 `SendMessage(WM_MOUSEACTIVATE)` 返回 3 作为
    「焦点已保持」的证据，指标无误，但焦点仍被抢占。判定焦点是否丢失，须以实际键盘输入为准。
    (3) **机制不通时应回溯根因，而非逐层修补后果**：六版 hack 每版都在处理上一版的
    边界情况，而实际的冲突只有一个：该样式与 WPF 菜单的前提相冲突。
    在需要时将其让开，问题连同此前的补丁一并消失。

19. **判断编译成功应依据退出码，不应 `grep` 编译输出。**
    `build.sh` 的输出为中文（GBK），在 Git Bash 中 `grep -E "CS[0-9]"` 会将其视为二进制文件，
    仅返回一句 `Binary file (standard input) matches`，**错误行全部被吞掉**。
    曾因此产生误判：编译实际报 `error CS1661` 失败，却被认为成功，测试的是一个**旧的 exe**，
    于是出现「修改代码无效果」的假象，并为此浪费了排查时间。
    正确做法：`./build.sh; echo $?`（非 0 即为失败），或将输出重定向至文件后按行查看。

20. **「全屏自动隐藏」的判定在四个方面均存在问题（均已实测）。**
    * **坐标空间不可混用**：判定全程仅使用 Win32（`GetWindowRect` 与 `GetMonitorInfo`，
      同一进程内均为物理像素），**绝不可与 WPF 的 `SystemParameters` 混用**（后者为 DIP 逻辑坐标）。
      本机为 1920x1080 @ **125%**，混用即产生「最大化窗口被误判为全屏」这一经典缺陷。
    * **必须「精确相等」，不可用「包含」**：实测 Windows 10 下最大化的普通窗口矩形为
      `-9,-9,1929,1039`，**大于显示器 `0,0,1920,1080`**（最大化时隐形边框会外扩）。
      使用「包含」会将每一个最大化窗口都判定为全屏。附带说明，任务栏未隐藏时最大化窗口的下边又小于显示器，
      因此「精确相等」同时也将其排除。
    * **「恰好铺满整屏」的窗口数量众多，不等同于在运行游戏**：实测本机现场即存在
      桌面 `#32769`、NVIDIA 覆盖层 `CEF-OSC-WIDGET`、输入法宿主 `TextInputHost`，
      三者均精确满屏。因此除类名黑名单外，还须排除带有
      `WS_EX_TOOLWINDOW` / `WS_EX_LAYERED` / `WS_EX_NOACTIVATE` 的窗口，
      置于最顶层的辅助窗口一律带有这几个样式。执行完整枚举后，通过数为 **0**。
    * **必须按 pid 排除自身**：菜单的点击接收层与**整块虚拟屏幕同大**，
      若不排除，它会被判定为「全屏游戏」，导致桌宠自行隐藏。
    * **失败模式是安全的**：在真正的独占全屏下 DWM 本就不合成其他窗口，桌宠根本无法绘制。
      因此需要解决的只有**无边框窗口化全屏**，而这恰是可精确测量的模式。
    * **采用轮询而非 `SetWinEventHook`**：游戏常以管理员权限运行，
      非提权进程注册的前台事件钩子收不到通知，而 `GetForegroundWindow` 轮询不受影响。
    * **实测正面验证**：原神（`UnityWndClass`）全屏时窗口矩形与显示器精确相等、
      `exStyle=0x00000000`，干净通过所有过滤器，桌宠正确隐藏且位置保留。
      （运行 `tools\verify-fullscreen.ps1` 可随时复现，无需真正启动游戏。）

21. **编译前必须先退出正在运行的 `Pet.exe`，否则会产生 `CS0016`。**
    桌宠运行时 `bin\Pet.exe` 被占用，`build.sh` 会在最后一步失败：
    `error CS0016: 未能写入输出文件...另一个进程正在使用此文件`。
    需要注意的是**前 5 个 exe 照常编译成功，仅 Pet.exe 失败**，
    且错误信息具有误导性，第一反应容易怀疑编译环境损坏。
    应先执行 `Stop-Process -Name Pet -Force` 再编译。

    若希望它**正常退出并保存配置**，则需额外处理：`Process.MainWindowHandle` 对桌宠返回 **0**
    （原因是 `ShowInTaskbar=false`），因此 `CloseMainWindow()` 无效（返回 False，不会执行到 `SaveConfig()`）。
    必须自行 `EnumWindows` 定位窗口并发送 `WM_CLOSE`，才会走完
    `app.Run()` 返回、`SaveConfig()` 这条路。

22. **在 Git Bash 中拼接 Windows 路径时，不要让变量紧跟反斜杠。**
    `"D:\ClaudePet\tools\$s.ps1"` 不会展开 `$s`：`\$` 在双引号内属于转义，
    整条路径变为字面的 `D:\ClaudePet\tools$s.ps1`（且反斜杠丢失）。

    **该问题在 2026-09-12 一天之内出现三次**，每次症状不同，因此尤其难以形成条件反射：
    * 第一次：`Cutout.exe 源图 "…\cut\$2.png"`，三个输出**一个都没有生成**，
      工具却仍以退出码 0 结束、仍打印「已写出 …」。更严重的是它**在项目中留下了残留文件**：
      整理磁盘时清除的 10.4MB `assets\cut$2.png*` 即为此次的残留，而当时并未被发现。
    * 第二次：`"$O\\$src.cs"` 编译旧 exe 进行 A/B 对比，csc 报 `找不到源文件 …\old$src.cs`。
    * 第三次：上述 `verify-*.ps1` 的循环，三个脚本全部返回 `EXIT=127`，
      报 `-File 参数实际参数 D:\ClaudePet\tools$s.ps1 不存在`。

    对策（按推荐程度排序）：
    (1) **`cd` 到目录内使用相对文件名**，完全不拼接路径，最为干净，csc 场景尤其适用；
    (2) **一律使用正斜杠**：`"D:/ClaudePet/tools/$s.ps1"`。
    注意 `csc` 属于例外（它会将路径中间的 `/` 当作选项前缀，`build.sh` 中已有记录），
    因此向 csc 传递路径应采用方案 (1)；
    (3) 确需使用反斜杠时，将反斜杠单独放入变量：`BS='\'`，再使用 `"$dir$BS$name"`。

    另外，Git Bash 会将 `/tmp/x` 自动转换为 `C:\Users\...\Temp\x`（MSYS 路径转换），
    因此将 `/tmp/...` 传给 Windows 程序通常可用，不应见到正斜杠就认为一定有误。

23. **`git clone` 之后无法编译：`bin\` 目录不存在。**
    `git` **不跟踪空目录**，而 `bin\` 中只有被忽略的 exe，因此克隆后并不存在该目录。
    csc 也不会代为创建，于是第一步即失败：

    ```
    bin\CSC5D1E14972699459CBB8E8D75C1B8231.TMP: error CS1567: 生成 Win32 资源时出错: 系统找不到指定的路径
    ```

    该报错具有很强误导性：文字为「生成 Win32 资源出错」，**完全看不出真正原因是
    「输出目录不存在」**，第一反应会怀疑编译器损坏。本机由于 `bin\` 早已存在，
    该缺陷一直未暴露。**也就是说在此修复之前，该仓库克隆到任何其他机器都无法编译。**
    修法是在 `build.sh` 中添加一行 `mkdir -p bin`（已添加）。

    **教训**：收尾阶段执行的「从零克隆再编译」验收，其价值远高于在本机反复运行。
    本机上所有历史文件均存在，天然不会遇到此类问题。

24. **抠图当前采用「背景色键控」，这是经过大幅简化后的结果，不宜直接沿用其简化形式。**
    当前做法可以一句话概括：**删除所有属于背景色的像素**。背景参考色取自图像最外
    `BgFrame`(20px) 那一圈的均色，容差为 ±30（第 3 个参数可调）。

    此前无法这样做的原因：上一版素材的背景为奶油色，与人物皮肤仅相差 **5**
    （面部 `(253,240,225)` 对背景 `(253,246,230)`）。阈值放宽会切掉人物，收窄则保留背景，
    无论如何调整都是错的。当时只能改用**几何判据**（深色描边膨胀为「堤坝」，再自四边漫水），
    它确实能将人物抠出，但带有两个无法消除的代价：

    - **边界切在描边外沿，会将角色自带的白色贴纸边一并切掉**；
    - 被轮廓围死的背景块（发卷中间的孔洞）漫水无法进入，需再补充一道颜色判据加以识别，
      而这道判据相当脆弱：实测同一块残留物在 8 张图中的「颜色吻合度」可从 15% 跃升至 79%
      （原因是「距它最近的那块背景」会随人物姿势变化），阈值无论如何设定都会漏判或误伤。

    2026-09-12 将素材重做为纯青背景后，上述问题一并消失。因此：

    > **更换素材时选择一块与角色明显不同的纯色背景，比事后修补算法划算得多。**
    > 这可能是本项目最有价值的一条经验：此前数轮均在修补算法，而真正的解法是更换素材。

    键控方案附带得到的两项结果：
    - 角色自带的白色描边与贴纸边**完整保留**（它属于画稿的一部分，不是背景）；
    - 被轮廓围死的背景色也一并删除。由于是逐像素判定，**完全不考虑连通性**，
      因此不需要「二次抠图」。

    **两个必须了解的边界：**

    - **容差 `KeyTol` 不可随意放宽。** 实测人物中最接近背景色的是**眼睛的青蓝高光**，
      与青色相差 **45**；设置到 45 以上会将眼睛高光当作背景挖除。当前取 30，两侧均有余量。
      （诊断中的「边框内吻合 %」是判断「该图是否适合此抠图方式」的体检指标，背景非纯色时该值会下降，
      届时它会**明确警告**，而不是默默输出一张质量不佳的图。）
    - **`KeepLargestComponent` 会将「不属于背景色、又与人物不连通」的内容一并丢弃。**
      实测素材右下角存在「豆包AI生成」水印文字，即由此被移除。9 张图中被丢弃的连通块
      **全部**位于 `(1481~1762, 2239~2300)` 这一角落，没有一块位于人物上。
      若将来画稿中存在**脱离人物的**装饰（飘带、星星、独立道具），该步骤会将其丢弃，
      届时需将「只保留最大连通块」改为「按面积筛选」。**更换素材后须专门确认这一点。**

    **验收依赖一个客观指标，而非肉眼**：诊断中的「残留自检」。
    由于是逐像素删除，它**必然报告 0**。保留该项是为了在将来改回「按块判定」时能立即察觉。

    旧版几何实现保存在 git 历史中（`git show HEAD:src/Cutout.cs`），未删除，只是不再使用。

25. **右键改为双击后，那 1/3 秒的迟滞无法避免；托盘图标有四个必踩的问题。**
    （2026-09-12：点击语义改为**左键说话 / 右键单击切换状态 / 右键双击弹出菜单**）

    **迟滞为何无法避免**：系统必须等待确认「不再点击第二下」，才能判定是单击而非双击的前半部分。
    因此右键切换状态存在 `RightDblClickMs`(350ms) 的延迟，这属于**信息不足**，不是实现缺陷。
    反向做法（先切换状态，判定为双击后再撤销）会让状态**在视觉上闪现一次**，效果更差。
    同一判定也用于验证脚本：`tools\verify-menu.ps1` 注入的是**双击**，
    且两下间隔必须 `< 350ms`，否则它将永远等不到菜单，只报告一个难以理解的 FAIL。

    **托盘图标（`NotifyIcon`）的四个问题，均为社区中反复出现的：**

    - **`csc.rsp` 默认已引用 `System.Windows.Forms.dll` 与 `System.Drawing.dll`**，
      **不应再显式 `/r:` 一次**，否则报 `CS1703 重复的程序集`
      （同一问题在 `build.sh` 的注释中已为 `System.Web.Extensions` 记录过）。
    - **`Icon` 未设置，或 `Visible` 未置为 true，图标即不显示**，且不会报错。
      此处图标是从素材**现场生成**的（`Bitmap.GetHicon()`），因此还须记得
      **`DestroyIcon` 释放句柄**，否则会泄漏 GDI 句柄。
    - **退出前必须 `Visible=false` 并 `Dispose()`**，否则托盘中会残留一个**幽灵图标**：
      进程已退出而图标仍在，需鼠标划过才会消失。此处已在 `app.Exit` 与 `win.Closed`
      两条路径上都挂了收尾逻辑（菜单退出走前者，关闭窗口走后者）。
    - **`NotifyIcon.Text` 在 .NET Framework 下上限为 63 字符**，超出会抛出 `ArgumentException`。
      提示文字中包含状态名，因此已按上限截断。

    **编写 `System.Drawing` / `System.Windows.Forms` 相关代码时应全部使用全名，不要添加 `using`**：
    这两个命名空间与 `System.Windows.Media` 存在大量同名类型
    （`Color` / `Brush` / `Point` / `Size` / `Application` 等），添加 `using` 会使整个文件混乱。

    **手动隐藏与全屏自动隐藏必须是两个独立字段**（`hiddenByUser` 与 `petHidden`）。
    若共用同一个字段：手动隐藏之后切出全屏时，全屏逻辑的「恢复」会调用
    `ShowPetAfterFullscreen()` 将宠物唤回，而该函数只检查 `petHidden`，并不知道
    这是手动隐藏。两者唯一的交叉点是 `CheckFullscreen()` 开头的 `if (hiddenByUser) return;`。

    **气泡动画与 `--shot` 相互冲突**：`ShotMode()` 渲染的是**当前这一帧**，
    若气泡正在执行「从 0.72 倍放大」的动画，截取到的将是缩小的、半透明的气泡，
    离屏验证便失去意义。因此 `ShowLabel` 的 `animate` 参数**默认为 false**，
    `--shot` 与 hook 气泡走这条路径，只有左键说话才传入 true。

## 资源占用

| 项目 | 数值 |
|---|---|
| 磁盘 | `D:\ClaudePet\` 约 64 MB。构成：抠好的姿势图 31MB，原始图 29MB，运行时素材 3MB，代码与文档 0.4MB |
| **C 盘占用** | **0**（编译器为系统自带） |
| 运行内存 | 约 90 至 105 MB（2 倍素材比 1 倍多占约 15MB） |
| 全屏检测 | 每 500ms 两次 `user32` 调用，实测开销可忽略；**隐藏期间会停掉动画定时器**，游戏时更为节省 |
| hook 开销 | 单次约 60 至 130ms，且**已采用异步握手**使 Claude Code 无需等待 |

异步握手（`PetNotify.exe` 第一行打印 `{"async":true}`）是官方插件采用的机制，可使 hook 不阻塞会话。
若所用 Claude Code 版本上该机制存在异常，设置环境变量 `CLAUDE_PET_SYNC=1` 可退回同步模式。

- **点击穿透模式**：平时不拦截鼠标点击，通过热键临时恢复。
  暂不实现的原因：它需要 P/Invoke 修改窗口样式并注册全局热键；一旦热键注册失败，
  将得到一只无法点击的宠物，反而造成卡死。若要实现，须确保稳定。

- 好感度与成长系统、摸鱼模式
- 音效
- 多显示器位置更细致的处理

- **`error` 状态**：无需新素材即可实现。为 idle 的帧烘焙一层红色蒙版作为第 5 行，
  清单添加一条即可，`Pet.cs` 无需修改。

  若改为「偏向身体中心」，会更接近歪头而非整体晃动。

  改为自行编写的面积平均滤波可在非整数倍降采样时获得更好的抗锯齿效果。
