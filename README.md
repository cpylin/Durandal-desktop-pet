# Claude Pet ——  Claude Code 桌宠

一只趴在桌面角落的小家伙，实时反映 Claude Code 在干什么：思考、跑命令、等你确认、干完了、报错了。

**零工具链安装**：用 Windows 自带的 C# 编译器构建，不需要装 Rust / Python / .NET SDK / Node。
**零 C 盘占用**：全部文件在 `D:\ClaudePet\`，编译器是系统自带的。

当前进度：**阶段 1（已可用）**。形象已从占位素材换成**崩坏三 幽兰黛尔 Q 版**（8 个状态各有专属姿势）。

> 想了解**为什么这么设计**（架构、抠图算法、验证方法、可复用的套路），看 **[NOTES.md](NOTES.md)**；
> 本文偏使用说明和踩坑清单。

## 想学点什么的话，从这里看

这个项目不大（约 3700 行），但有几块**密度很高**的东西，都是真踩过坑之后才写下来的。

**含金量排序**（不是阅读顺序）：

| 看什么 | 在哪儿 | 为什么值得看 |
|---|---|---|
| **抠图算法** | `src\Cutout.cs` | 全项目技术含量最高的一块。没有 alpha 通道、浅色背景的图，靠「堤坝膨胀 + 连通块 + 封闭孔洞判定」把人物抠出来。它的**诊断产物设计**也值得学：每次运行都吐 `.check/.mask/.alpha` 三张图和一份数值报告，**让算法的中间结果肉眼可验** —— 这类"看不清的过程"最该这么设计 |
| **窗口的坑** | `src\Pet.cs` 的注释 | 分层窗口截不到图、点击不抢焦点要三个机制同时上、WPF 右键菜单为什么关不掉……这些是**搜也未必搜得到**的经验。每条注释都标了"错误信息会把你带向哪个错误方向" |
| **零安装构建** | `build.sh` | 只用系统自带的 `csc.exe`，不装任何 SDK。顺带能学到 csc 把 `/` 当选项前缀、Git Bash 会吃掉 `/nologo` 这类诡异行为 |
| **图像流水线** | `src\SheetGen.cs` | 「一张图 → sprite sheet + 清单」的设计：清单和 sheet 由**同一个工具**生成，所以永远对得上。**自洽性优于灵活性**的一个具体样本 |
| **状态机与降级** | `src\Pet.cs` 的 `SetState` / `Tick` | 自动衰减、会话判死、非循环动画回落 —— 一个"不许卡住"的状态机是怎么写的 |

**建议的阅读顺序**：

1. 本文，尤其 **[已知坑](#已知坑改代码前务必看)** 那 21 条 —— 先知道哪里会翻车
2. [NOTES.md](NOTES.md) 第 2 节 —— 桌宠本体的设计取舍
3. `src\Pet.cs` 的文件头注释 + `BuildWindow()` —— 拿到整体骨架
4. 想深挖哪块再进哪块（抠图 / 素材 / 网络对接）

**几条反直觉但通用的教训**（散布在各处注释里，这里汇总）：

- **别用"代理指标"代替结果验证**：曾经拿 `SendMessage(WM_MOUSEACTIVATE)` 的返回值当作"焦点保住了"的证据 —— 指标没错，焦点照样被抢。要验"焦点有没有丢"就去真打字。
- **一个机制说不通时，回头找根因，别一路修补后果**：右键菜单关不掉这个现象曾经修了六版，每版都在解决上一版的边界情况；真正的麻烦只有一个，把它让开，问题连同补丁一起消失。
- **判据要"精确"，不要"宽容"**：全屏检测用"窗口矩形**包含**显示器"会把每个最大化窗口都误判成全屏（实测最大化窗口的矩形比显示器还大）；改成"**精确相等**"才对。
- **别用全局指标代替逐项指标**：素材缩放一度让所有状态共用一个像素比，加入一张低分辨率图后，那张就显示得只有别人 1/3 大。**分辨率不一致时，全局共用一定是错的**。
- **构建成功看退出码，不要 grep 输出**：中文输出是 GBK，`grep` 会把它当二进制文件、把错误行全吞掉 —— 然后就拿着一个旧 exe 测了半天"改了没效果"。

**不建议照抄的地方**（这个项目有意的局限，说清楚免得被误导）：

- 6 个 exe 各自独立编译、**互不共享代码** —— 于是 PNG 保存、建目录这类逻辑重复了 4~5 份。这是"零安装 + 每个工具都能单独跑"换来的代价，**不是好设计**。
- `Pet.cs` 单文件 1649 行，其中右键菜单一个函数 159 行。够用，但不是一个好的分层示范。
- 没有自动化测试。验证靠 `tools\` 下两个 PowerShell 脚本 + 人工看界面。

## 用起来

### 1. 编译

在 Git Bash 里：

```bash
cd /d/ClaudePet && ./build.sh
```

### 2. 素材

已经带了一套（幽兰黛尔 Q 版），不用做任何事。想回到占位素材（蓝色果冻）：

```bash
./bin/MakeSprites.exe
```

它会重写 `assets\pet.png` + `assets\pet.json`（自洽的，见坑 14）。
换成自己的形象走另一条流水线，见下面「换成你自己的形象」。

> **磁盘占用可以随时清掉一大半**：`Cutout.exe` 每跑一次都会在输出旁边留下 4 个文件 ——
> `.check.png`（洋红底检查图）、`.mask.png`（抠漏标记）、`.alpha.png`（灰度 alpha）、
> `.txt`（连通块诊断）。**它们纯粹是给人看的，删掉不影响任何东西**，下次跑 Cutout 会重新生成。
> 当前仓库里已经清过了（原来 36 个共 60MB）。
> `youlandaierQban\` 里的原始图**别删** —— 那是 `Cutout.exe` 的输入，删了就没法重新抠图。

### 3. 启动桌宠

双击 `bin\Pet.exe`，或：

```bash
/d/ClaudePet/bin/Pet.exe &
```

宠物默认出现在**屏幕右下角**。

### 4. 接入 Claude Code

```powershell
powershell -ExecutionPolicy Bypass -File D:\ClaudePet\install-hooks.ps1
```

会先备份你的 `~\.claude\settings.json`，然后写入 8 个 hook 事件。**重启 Claude Code 生效**。

卸载：

```powershell
powershell -ExecutionPolicy Bypass -File D:\ClaudePet\install-hooks.ps1 -Uninstall
```

想先看看会改什么，加 `-DryRun`。

### 5. 开机自启（已配好）

**最方便的方式：对着桌宠右键 →「开机自启」**（菜单里带勾选状态，点一下就切换，
气泡会回一句「已开启开机自启」/「已取消开机自启」）。

想用命令行（比如写脚本、或者桌宠没在跑的时候）：

```powershell
powershell -ExecutionPolicy Bypass -File D:\ClaudePet\install-autostart.ps1           # 开启
powershell -ExecutionPolicy Bypass -File D:\ClaudePet\install-autostart.ps1 -Status   # 查看
powershell -ExecutionPolicy Bypass -File D:\ClaudePet\install-autostart.ps1 -Disable  # 关闭
```

两条路读写的是**同一个注册表值**，所以永远同步；菜单项的勾选状态也是每次打开菜单时现读的，
不会显示成过期的状态。

写的是 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里一个叫 `ClaudePet` 的项 ——
**只动当前用户、不需要管理员**，也不碰任何系统级设置。

为什么用注册表 Run 键而不是把快捷方式丢进「启动」文件夹：**启动文件夹在 C 盘**，
而这个项目的原则是 C 盘零占用 —— 注册表项不新增任何文件。而且任务管理器的「启动」标签页里
一样能看到它、也能直接在那儿禁用（两处是同一个开关）。

## 状态映射

| Claude Code 事件 | 宠物状态 | 现在这个形象（幽兰黛尔） | 占位素材（8 个状态齐全） |
|---|---|---|---|
| `SessionStart` | awake | 双手握拳 + 两次小跳，气泡「**会话开始 · 项目名**」 | 蹦一下打招呼 |
| `UserPromptSubmit` | think | 盘腿托腮 + 冒省略号 | 歪头，冒省略号 |
| `PreToolUse` | work | 坐在书桌前写字 + 快节奏小抖 | 快速抖动，动感线 |
| `PostToolUse` | think | 盘腿托腮 + 省略号 | 回到思考 |
| `PostToolUseFailure` | error | 抱膝缩起来发抖（眼里含泪） | × 眼、波浪嘴、冒汗 |
| `Notification` / `permission_prompt` | alert | 挥手 + 感叹号——**在等你确认** | 睁大眼、感叹号 |
| `Notification` / `idle_prompt` | sleep | 抱着枕头睡在云上 + 慢呼吸 | 闭眼，冒 Z |
| `Stop` | done | 举拳欢呼蹦跳 + 闪星星 | 欢呼跳跃，闪星星 |
| `SessionEnd` | sleep | 同上（睡了），气泡「**会话结束 · 项目名**」 | 睡了 |

当前形象：**8 张图，一个状态一张、没有任何复用**（hooks 会发的 8 个状态全都有专属姿势了）。
`assets\cut\` 里的抠图按**姿势**命名（不是按状态命名）—— 这样以后重新分配状态时，
文件名不会变得自相矛盾：

| 状态 | 素材（姿势） | 动作 |
|---|---|---|
| idle | `akimbo.png` 双手叉腰等着 | 轻微呼吸浮动 |
| think | `sit.png` 盘腿托腮 | 轻轻歪头 + 「…」 |
| work | `desk.png` 坐在书桌前写字 | 快节奏左右小抖 |
| alert | `wave.png` 挥手 | 弹跳 + 「!」 |
| done | `cheer.png` 举拳抬腿欢呼 | 一次大跳 + 星星 |
| awake | `clasp.png` 双手握拳 | 两次小跳 |
| sleep | `pillow.png` 抱枕头睡在云上 | 慢呼吸（3fps） |
| error | `teary.png` 抱膝缩着发抖 | 小幅快速摇晃 |

> **各状态的视觉大小**由 `SheetGen.cs` 里的 `ScaleAdjust()` 手工微调。为什么需要它：
> 光把 bbox 高度统一是**不够**的 —— 站姿里"头"只占 bbox 高的 ~23%，
> 盘腿/蜷缩的姿势能占到 ~32%，于是同样 bbox 高度下，**坐着的几个头明显更大**，
> 看着像"凑近了"。现在的值：think 0.93、sleep 0.88、error 0.86（坐/蜷的缩小），
> work 1.05（有书桌撑满画框、人反而显小）。改这几个值之后要重新生成 sheet 并**用眼睛验收**，
> 它们是审美判断，不是算出来的。

万一来了清单里没有的状态名（改了 hook、或加了新状态还没做素材），仍然会**安全地退回 idle**，
不会崩 —— 这是保底逻辑，不是当前有状态缺素材。

> `assets\cut\` 里的 `stand.png`（站立点赞）是**备用**的：它原来占着 idle，
> 换成上面那张"双手叉腰"的待机图之后就没在用了。想换回去就把生成命令里的
> `idle=` 改回 `stand.png` 重新生成一次。

> `sit.png` 那张原图里她**坐在一朵云上**。抠图时把云去掉了 —— 为了和另外几张一致
> （干净切口、不带那圈淡米白的贴纸边）。想要云的话：把 `Cutout.exe` 的暗色阈值
> 改成 200 重抠（`Cutout.exe "...\youlandaierQban4.png" "...\assets\cut\sit.png" 200`），
> 云会留住，代价是人物周围会带一圈很淡的贴纸边。

`done` / `awake` 播完会自己回到 `idle`；`alert` 会一直举着手直到你处理。
另外有兜底：卡在 think/work 超过 90 秒（会话异常结束）会自动回 idle。

## 交互

- **拖动**：按住左键拖（松手后位置会记住）
- **单击**：按固定顺序切到下一个状态，气泡里显示状态名 ——
  待机 → 在想事情 → 正在干活 → 等你确认 → 干完了 → 回来了 → 睡着了 → 出错了 → 回到待机。
  不用开右键菜单就能把八个姿势都看一遍。
  注意 `等你确认` 和 `睡着了` 是**持久**状态，点进去会停在那儿（那是它们本来的语义），
  再点一下就继续往下走；下一个 Claude 事件也会把它拉回正确的状态。
- **右键菜单**：大小、透明度、回到右下角、重新载入素材、测试各状态、**开机自启**、
  **全屏游戏时自动隐藏**（都带勾选状态，随时开关）、退出
- **再双击一次 `Pet.exe`**：不会开出第二只——已经在跑的那只会冒泡说「我在这儿！」，
  万一它跑到屏幕外了（改过分辨率、拔过显示器），会自己挪回右下角。
  只有它占着位置却不回应时，才会弹一张 8 秒后自动消失的提示卡片。
- 窗口是 `WS_EX_NOACTIVATE` 的——**点它不会抢走你编辑器的焦点**（这条以前是假的，见坑 18）
- 位置/大小/透明度自动记住，存在 `config.json`

### 全屏游戏时自动躲开

你进全屏游戏（原神之类）它会**自己藏起来**，退出全屏**自己回来**，位置不变。
开关在右键菜单里（`全屏游戏时自动隐藏`，**默认开**），存在 `config.json`。
判定方式：500ms 轮询一次前台窗口，矩形和显示器**精确相等**才算全屏（连续 2 次才动作，约 1 秒）。

- 真·独占全屏下 DWM 本来就不合成别的窗口，桌宠在那模式下**压根画不出来** ——
  所以这个功能真正要解决的只有**无边框窗口化全屏**，而那恰恰是能精确测出来的模式。
  换句话说：**检测失败也是安全的**。
- 全屏视频、F11 浏览器同样会触发隐藏（按"别挡画面"的语义，这是想要的）。
- **误判了怎么办**：万一它在你不想躲的时候躲了，右键是点不到的 ——
  **再双击一次 `Pet.exe`** 就能叫回来，而且会顺手把这个功能**关掉**并告诉你。
  （不关掉的话下一轮采样又把它藏回去，用起来就像"双击没用"。）想开再右键勾回来。
- 多显示器：任一台显示器上有全屏窗口就躲开，不细分"桌宠是否在同一块屏"。

## 换成你自己的形象

两个工具一条流水线，**不用改代码、不用重新编译**：

```bash
# 第 1 步：抠图。输入随便什么图（JPEG/PNG 都行，程序自己认格式，不信扩展名）
./bin/Cutout.exe "D:\ClaudePet\youlandaierQban\youlandaierQban1.png" "D:\ClaudePet\assets\cut\stand.png"

# 第 2 步：生成 sheet + 清单。每个状态各一张图；某个状态不写就沿用"默认"那张
./bin/SheetGen.exe "D:/ClaudePet/assets/cut/cheer.png" ^
    idle=D:/ClaudePet/assets/cut/akimbo.png    ^
    think=D:/ClaudePet/assets/cut/sit.png  ^
    work=D:/ClaudePet/assets/cut/desk.png    ^
    alert=D:/ClaudePet/assets/cut/wave.png   ^
    awake=D:/ClaudePet/assets/cut/clasp.png  ^
    sleep=D:/ClaudePet/assets/cut/pillow.png  ^
    error=D:/ClaudePet/assets/cut/teary.png
```

想加状态（比如再加一个"庆祝"）：在 `SheetGen.cs` 的 `States` 数组**末尾**加一条、
给它写个动作分支（按**名字**认，见 `DrawFrame`），然后重新生成清单 ——
`Pet.cs` 认的是清单里的名字，**不用改代码**；点击循环也会自动带上新状态。
`awake` 曾经是"复用别的状态的帧"（`--awake=<状态名>`），现在它自己占一行；
两种写法都支持，但如果状态表里已经有 `awake`，就不会再补那条复用的（否则 JSON 里会有两个同名键）。

两条约定（都是踩过才写下来的）：

- **缩放比例每个状态各自算**（按各自的图适配到最大，屏幕上高度一致）。
  曾经"优化"成全局共用一个像素比，结果换上一张低分辨率的图
  （658x860 vs 另外三张 1760x2304）之后，那张显示得只有别人 1/3 大 ——
  **素材分辨率不一致时，全局共用像素比一定是错的**。
- **动作参数与画稿无关**：换姿势图不用改 `SheetGen` 里的动作数值，
  它们描述的是"这个状态该有什么感觉"。

每一步都会输出**能肉眼检查的图** —— 这不是可选项，因为抠图和边缘的问题只能靠看图判断：

| 文件 | 看什么 |
|---|---|
| `<名字>.png.check.png` | 合成到**洋红底**上：残留背景一眼可见（奶油色在洋红上藏不住） |
| `<名字>.png.mask.png` | 原图上把"判成背景抹掉"的像素涂红：抠漏人物一眼可见 |
| `<名字>.png.txt` | 数值诊断：bbox、背景占比、被丢掉的连通块、每个封闭块的色差 |
| `<名字>.png.alpha.png` | 只看 alpha 的灰度图（头发里一片灰 = 填充漏进去了） |
| `bin\Zoom.exe <图> <x> <y> <w> <h> <倍数> <出.png>` | 裁一小块放大。给两张图就并排对比，边缘细节靠它看 |

```
keep  240 700        # 反过来：把误抹的恢复成人物
```


### 画布和清单的约定

- **屏幕上的显示尺寸 = `frameWidth / sheetScale`**。`frameWidth/frameHeight` 是 sheet 里每格的
  **像素**尺寸，`sheetScale` 是像素密度（生成器默认 2 倍：100% DPI 下是超采样，
  把桌宠放大到 2 倍也不糊，代价是文件大一点）。
- **清单永远由生成器自己写**（`SheetGen.exe` 或 `MakeSprites.exe`）：手改 sheet 尺寸却忘了
  改清单是必然踩的坑，所以干脆不给人改的机会。
- 想换回占位素材：跑 `./bin/MakeSprites.exe`（它会重写 pet.png + pet.json）。
  你 `assets\cut\` 里的抠图不受影响，随时能用 SheetGen 再生成回来。

**注意 WPF 不支持 GIF**，所以必须用 sprite sheet，不能直接塞动图。
自己画素材可以用 Aseprite 或 Piskel（都免费）。

改完素材后不用重新编译，右键「重新载入素材」即可（窗口尺寸也会跟着重算），或者重启桌宠。

## 已知坑（改代码前务必看）

这些都是实际踩过的，不是理论：

1. **csc 把 `/` 当选项前缀，即使它出现在路径中间。**
   `D:/a/b.cs` 会被拆成 `D:` + `b.cs`，报「找不到源文件」。
   传路径**必须用反斜杠**，`build.sh` 里已经这么做了。

2. **Git Bash 会把 `/nologo` 这类参数转成路径。**
   编译前要 `export MSYS_NO_PATHCONV=1`。

3. **别显式引用 `System.Web.Extensions`。**
   csc 自带的 `csc.rsp` 已经引了它，再引一次报 CS1703「重复的程序集」。

4. **PowerShell 脚本含中文必须存成 UTF-8 with BOM。**
   否则 PowerShell 5.1 按 GBK 解析，直接语法报错。`install-hooks.ps1` 已加 BOM。

5. **`Grid` 的 `RowDefinition` 不设高度时默认是 star（各占一半）。**
   128px 的精灵图会被塞进一半高度的槽位而裁掉。
   必须显式设 `Auto` / `Star`。

6. **WPF 透明窗口是分层窗口，`CopyFromScreen` 截不到它。**
   要验证渲染请用 `--shot` 离屏渲染，不要靠截图。

7. **`Pet.exe` 运行时无法重新编译**（文件被锁），先 `taskkill /F /IM Pet.exe`。

8. **编译器只支持 C# 5**：不能用 `$"..."`、`?.`、`nameof`、表达式体成员。
   `async/await` 可以用。

9. **hook 命令必须用 exec 形式，不要把状态拼进 command 字符串。**
   `"command": "D:\\ClaudePet\\bin\\PetNotify.exe awake"` 这种一整串的写法，
   Claude Code 会把它交给 shell 解析。Git Bash 里未加引号的反斜杠是转义符，
   路径被吃成 `D:ClaudePetbinPetNotify.exe`，于是每个 hook 都报
   `command not found`，桌宠全程收不到事件（表现为「桌宠没反应」，但 Pet.exe
   其实好好地在监听 47821）。
   正确写法是路径和参数分开：

   ```json
   { "type": "command", "command": "D:\\ClaudePet\\bin\\PetNotify.exe", "args": ["awake"], "timeout": 5 }
   ```

   `args` 存在时是 exec 形式——Claude Code 直接 spawn 这个 exe，不经过任何
   shell，所以反斜杠、空格、`$` 都不会被解析。`install-hooks.ps1` 已按此生成。

   排查提示：hook 一旦失败，Claude Code 会在会话里显示 hook 报错。如果桌宠没反应
   却没有任何报错，那多半是 Pet.exe 没在跑，而不是 hook 的问题。
   `netstat -ano -p UDP | grep 47821` 能看到 `Pet.exe` 就没问题。

10. **提示别用 `MessageBox`——不是它会失效，是它抢焦点。**
    对话框在系统里是正常的。（我一度以为这台机器会自动关弹窗，还写了测试；
    真相是我自己在点，见坑下面的注。）要避开它的原因是**桌宠整个设计就是不打断你**：
    模态框会抢走焦点、并且一直挡在那，直到有人专门去点掉它。
    → 用 `ShowNotice`：无按钮 + `Topmost` + `ShowActivated=false` + 8 秒后自己 `Close()`。
    没有「确定」可点，用户就不用为一条提示挪动鼠标。

    > 注：那条"机器会自动关弹窗"的错误结论是我自己造的，也是我删掉的。
    > 教训写在这儿免得再踩：观察到的 UI 现象如果机器前坐着人，**先问是不是他做的**，
    > 再考虑系统原因。当时那个 2~3 秒的"规律"看着挺像环境特性，其实正是人类点确定的速度。

11. **`ClampToScreen()` 在启动时是空操作。**
    它跑的时候 `win.Left` 还是 `NaN`（配置里的坐标在 `ApplyScale` 之后才赋到窗口上），
    函数第一行 `if (double.IsNaN(win.Left)) return;` 就直接返回了。
    于是 `config.json` 里一个屏幕外的坐标会让宠物**一声不吭地活在屏幕外**：
    进程在、UDP 在听 hook 事件、但桌面上什么都没有——看起来就像"程序根本没启动"。
    → 现在由 `EnsureVisible()` 兜底：启动时和收到"召唤"时各确认一次，看不全就回右下角。

12. **`SetState()` 的早退条件少了 `img.Source != null`，启动时窗口里什么都不画。**
    `state` 字段初值就是 `"idle"`，所以启动那次 `SetState("idle")` 命中
    `if (s == state && anims[s].Loop) return;` 直接返回，`img.Source` 一直是 null ——
    进程在跑、窗口大小位置都对、`IsWindowVisible` 也返回 true，但窗口里**完全透明**。
    看上去就是"桌宠根本没启动"，而它其实要等第一个 hook 事件到来才画出来。
    这个 bug 极难查：截图截不到（坑 6），`--shot idle` 渲染出来只有 11KB（正常 400KB）才露馅。
    → **`--shot` 把每个状态都渲染一次，是个值得养成的习惯**（9 个状态几秒钟的事）。

13. **抠图不能用颜色判据，要用几何判据。**
    幽兰黛尔的脸 `(253,240,225)` 和背景 `(253,246,230)` 只差 **5** —— 阈值定宽了切人物、
    定窄了留背景，怎么调都是错的。而且她的浅金发还刚好落在背景里某些黄色样本的容差内。
    正确做法：把**深色描边**膨胀成"堤坝"（膨胀是为了封住描边的几像素断口），
    从四边漫水，堤坝外面才是背景 —— 脸和背景同色也没关系。
    颜色只用来区分"封闭的缝"（要抹掉）和"封闭的人物部件"（要保留），
    实测两者分得很开：缝的均色差 3~9，人物部件 14~96。

14. **清单必须由生成器自己写，不要手改。**
    手改 `pet.json` 的 `frameWidth` 却忘了改 sheet（或者反过来），切出来就是一堆错位的碎图，
    而且不会报错。所以 `SheetGen.exe` 和 `MakeSprites.exe` 都自己写清单，
    两者各自自洽 —— 谁生成的 sheet 就由谁写清单。

15. **`EnsureVisible()` 必须在 `win.Show()` 之后调用。**
    在 `BuildWindow()` 里调过一次，那时窗口尺寸还没最终确定（`LoadSprites` 之后
    才会按清单重算），于是它按一个错误的尺寸判断，把宠物挪到了右下角、还写回了 `config.json`。
    判据本身没问题，**判断的时机**有问题。

16. **抠图的"堤坝半径"必须跟着图的大小走。**
    它封的是描边的断口，而断口宽度是按图的大小放大的：658px 宽的图 5px 够用，
    1760x2304 的图用 5px 就会漏 —— 浅色头发被整片当成背景吃掉（背景占比从 58% 涨到 68%），
    而**不会报任何错**。`Cutout.exe` 现在按图宽自动定（`W/160`，最小 5），
    也可以用第 5 个参数手动指定。
    查这类问题的方法：把半径从小到大扫一遍，看**背景占比**（诊断 .txt 里的"填充结果"）——
    漏的时候偏大，封住之后会有一个明显的拐点，再大也没有副作用。

17. **判断"单击还是拖拽"要比窗口坐标，不能比鼠标相对窗口的位置。**
    原来用 `e.GetPosition(win)` 在 `win.DragMove()` 前后取差值 —— 但 `DragMove()` 内部
    会移动窗口，这个差值会被污染：**明明是原地单击，也会被误判成拖拽**。
    实测症状：点一下宠物，它被挪走（而不是切状态），而且新位置还被写进了 `config.json`。
    现在比的是 `win.Left/Top` 的前后差（阈值 4px）—— 这是客观的"窗口到底动没动"。

    试过**自己实现拖拽**（用 MouseMove 自己挪窗口）来彻底绕开 DragMove 的脾气：
    点击判断确实干净了，但我那版拖拽自己有 bug（存进 `config.json` 的位置是错的）。
    更要紧的是：**用注入鼠标的脚本根本验不准拖拽** —— 注入的"松开"收尾不干净，
    窗口会继续跟着真实光标跑（这就是那次 config 里出现 1102,156 这种离谱坐标的原因）。
    结论：留用 DragMove（久经考验），**拖拽只能人工验**；合成鼠标能可靠验证的只有"单击"。

18. **"点它不抢焦点"要三个东西都上；而它会让右键菜单关不掉 —— 正确解法是"开菜单期间临时放开"。**
    这个项目一直声称窗口是 `WS_EX_NOACTIVATE` 的（README、代码注释、NOTES 都这么写），
    **但那是假的**：`ShowActivated=false` 只管第一次 `Show()` 不激活，WPF 不会因此加那个样式。
    实测 `GetWindowLong(GWL_EXSTYLE)` 是 `0x00080008`（TOPMOST|LAYERED）。后果：点一下宠物，
    你正在打字的输入框就失焦了 —— 这是最核心的一条体验承诺，一天都没真正生效过。

    修的时候发现**少一个都不行**：
    | 手段 | 单独用为什么不够 |
    |---|---|
    | `ShowActivated=false` | 只管第一次 Show |
    | `WM_MOUSEACTIVATE → MA_NOACTIVATE` 钩子 | 只拦"鼠标点击引发的激活"；**WPF 处理鼠标输入时自己还会主动激活窗口**，走另一条路 |
    | `WS_EX_NOACTIVATE` 样式 | 有效，但它让窗口**永远不可能失活** —— 而 WPF 右键菜单关闭的默认逻辑靠的正是"宿主失活" |

    于是有了那个副作用：**菜单能弹出、点空白处关不掉**。我为此绕了**六版**（采样鼠标状态、
    算菜单屏幕矩形、让菜单项"认领"点击、各种宽限与保险），每版都冒出新的边界情况：
    矩形算成 1×1、"打开菜单那一次按键被当成点击"、按住菜单项超过宽限时间菜单就自己关了……
    **全都是在和同一个根因的后果较劲。**

    → 第一步：**菜单打开期间把 `WS_EX_NOACTIVATE` 临时撤掉**
    （`MenuOpenedAllowActivate`），菜单项就能正常点了；关掉后（`MenuClosedRestoreNoActivate`）
    装回样式，并用 `SetForegroundWindow` **把焦点还给原来那个窗口**。
    代价：菜单开着时焦点会短暂离开你的编辑器（用菜单本来就该这样）。
    顺手删掉了前六版积累的约 140 行 hack。

    → 第二步（**点空白处仍然关不掉**，去查了社区才知道原因）：WPF 的 `ContextMenu`
    把"关闭"挂在**鼠标捕获**上 —— 原话是"它捕获鼠标，控件又被写死成'鼠标一失去捕获就关'，
    算设计缺陷，可以用原生 `Popup` 绕开"。所以在我们这种窗口上它就是不关，跟激活无关。
    → 最终解法：菜单打开期间铺一层**几乎全屏的"点击接收层"**（`ShowMenuCatcher`），
    让**操作系统的命中测试**去决定里外，不再猜。三个要点：
    ①它得是**几乎**透明（`alpha=1`）而不是全透明 —— 全透明的分层窗口点击会穿透过去、接不到；
    ②必须用 `SetWindowPos` **明确排在菜单 popup 后面**，否则它会把菜单自己的点击吃掉
    （那正是"菜单项点不动"的成因）；③拿不到菜单窗口句柄就**不铺**（宁可关不掉，也不能弄坏菜单）。

    **三条教训**：
    ①文档里的断言（尤其"最重要的那条"）也要实测，别继承。
    ②**别用"代理指标"代替结果验证**：我曾用 `SendMessage(WM_MOUSEACTIVATE)` 返回 3 当作
    "焦点保住了"的证据 —— 指标没错，焦点照样被抢。要验"焦点有没有丢"就去真打字。
    ③**一个机制说不通时，回头找根因，别一路修补后果**：六版 hack 每版都在解决上一版的
    边界情况，而真正的麻烦只有一个 —— 那个样式和 WPF 菜单的前提冲突。
    把它在需要的时候让开，问题连同之前的补丁一起消失了。
19. **判断编译成功要看退出码，不要 `grep` 编译输出。**
    `build.sh` 的输出是中文（GBK），在 Git Bash 里 `grep -E "CS[0-9]"` 会把它当二进制文件、
    只回一句 `Binary file (standard input) matches` —— **错误行全被吞掉**。
    我就这么被骗过一次：编译明明报 `error CS1661` 失败，我以为成功了，测试的是一个**旧的 exe**，
    于是"改了代码没效果"，白白怀疑了一阵子自己的改动。
    → 正确做法：`./build.sh; echo $?`（非 0 就是失败），或者把输出重定向到文件再按行看。

20. **「全屏自动隐藏」的判定，四处都是坑（全都实测过）。**
    * **坐标空间不能混**：判定全程只用 Win32（`GetWindowRect` + `GetMonitorInfo`，
      同一进程内同为物理像素），**绝不能和 WPF 的 `SystemParameters` 混用**（那是 DIP 逻辑坐标）。
      本机是 1920x1080 @ **125%**，混用就是"最大化窗口被误判成全屏"那个经典 bug。
    * **必须"精确相等"，不能用"包含"**：实测 Win10 下最大化的普通窗口矩形是
      `-9,-9,1929,1039` —— **比显示器 `0,0,1920,1080` 还大**（最大化时隐形边框会外扩）。
      用"包含"会把每个最大化窗口都判成全屏。顺带一提，任务栏没隐藏时最大化窗口的下边又小于显示器，
      所以"精确相等"同时也把它排除了。
    * **"正好铺满整屏"的窗口有一大堆，不等于在玩游戏**：实测本机现场就有
      桌面 `#32769`、NVIDIA 覆盖层 `CEF-OSC-WIDGET`、输入法宿主 `TextInputHost`，
      全都是精确满屏。所以除了类名黑名单，还得排掉带
      `WS_EX_TOOLWINDOW` / `WS_EX_LAYERED` / `WS_EX_NOACTIVATE` 的窗口 ——
      贴在最上面的辅助窗口清一色带这几个样式。跑完整枚举，通过数 **0**。
    * **必须按 pid 排除自己**：菜单的点击接收层是**整块虚拟屏幕大**的，
      不排除的话它会被判成"全屏游戏"，桌宠自己把自己藏起来。
    * **失败模式是安全的**：真·独占全屏下 DWM 本来就不合成别的窗口，桌宠压根画不出来。
      所以要解决的只有**无边框窗口化全屏**，而那恰恰是能精确测出来的模式。
    * **用轮询不用 `SetWinEventHook`**：游戏常以管理员权限跑，
      非提权进程注册的前台事件钩子收不到通知，`GetForegroundWindow` 轮询不受影响。
    * **实测正面验证**：原神（`UnityWndClass`）全屏时窗口矩形与显示器精确相等、
      `exStyle=0x00000000` 干净通过所有过滤器 → 桌宠正确隐藏、位置保留。
      （跑 `tools\verify-fullscreen.ps1` 可以随时复现，不用真开游戏。）

21. **编译前必须先退出正在跑的 `Pet.exe`，否则 `CS0016`。**
    桌宠在跑时 `bin\Pet.exe` 被占用，`build.sh` 会在最后一步失败：
    `error CS0016: 未能写入输出文件...另一个进程正在使用此文件`。
    阴险的地方是**前 5 个 exe 照常编译成功，只有 Pet.exe 失败**，
    错误信息又唬人，第一反应容易怀疑是编译环境坏了。
    → 先 `Stop-Process -Name Pet -Force` 再编译。

    想让它**正常退出并保存配置**得费点事：`Process.MainWindowHandle` 对桌宠返回 **0**
    （因为 `ShowInTaskbar=false`），所以 `CloseMainWindow()` 没用（返回 False，不会走到 `SaveConfig()`）。
    要自己 `EnumWindows` 找到窗口发 `WM_CLOSE`，才会走完
    `app.Run()` 返回 → `SaveConfig()` 这条路。

## 开销

| 项目 | 数值 |
|---|---|
| 磁盘 | `D:\ClaudePet\` 约 64 MB。构成：抠好的姿势图 31MB + **原始图 29MB** + 运行时素材 3MB + 代码文档 0.4MB |
| **C 盘占用** | **0**（编译器是系统自带的） |
| 运行内存 | 约 90~105 MB（2 倍素材比 1 倍多占约 15MB） |
| 全屏检测 | 每 500ms 两次 `user32` 调用，实测开销可忽略；**被隐藏期间会停掉动画定时器**，玩游戏时更省 |
| hook 开销 | 单次约 60~130ms，但**已用异步握手**让 Claude Code 不必等待 |

异步握手（`PetNotify.exe` 第一行打印 `{"async":true}`）是官方插件在用的机制，让 hook 不阻塞会话。
如果你的 Claude Code 版本上这个机制有异常，设环境变量 `CLAUDE_PET_SYNC=1` 可退回同步模式。

## 还没做的（阶段 2+）

- **点击穿透模式**：平时不挡鼠标点击，热键临时恢复。
  之所以先不做：它需要 P/Invoke 改窗口样式 + 注册全局热键，万—热键注册失败，
  你会得到一只点不动的宠物反而卡住。要做就要做稳。
- 多会话聚合、专注计时、统计面板
- 好感度/成长系统、摸鱼模式
- 音效
- 多显示器位置的更细致处理

素材侧还能再打磨的（都是可选的，不影响使用）：

- **`error` 态**：不用新素材就能做 —— 给 idle 的帧烤一层红色蒙版当第 5 行，
  清单加一条即可，`Pet.cs` 不用改。
- **旋转支点按状态混合**：现在统一绕脚底转（为跳跃服务）；`think` 那种小角度倾斜
  如果改成"偏向身体中心"，会更像歪头而不是整体晃。
- **降采样换成 box 滤波**：现在靠 WPF 的 `HighQuality`（实测边缘干净），
  换成自己写的面积平均滤波能在非整数倍降采样时更抗锯齿。
